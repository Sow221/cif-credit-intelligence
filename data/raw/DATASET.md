# Avalix reference dataset (synthetic)

> **Synthetic data.** No real person, client or institution is represented.
> Results obtained on this dataset demonstrate the method; they say nothing
> about real-world performance.

- This is the dataset on which all audit reports in `reports/` were computed.

## Known limitations

- **Latent risk factor.** The generator draws a hidden risk factor
  (`raw_score`, `p_default_true`) that drives the target. These two columns
  are kept in the file for transparency but are **forbidden as features**:
  the feature builder rejects them (anti-leakage guard). The phase A audit
  measured that this direct link contributes about 0.12 of ROC-AUC.
- **No real timestamps.** The temporal split uses `customer_id` order as a
  proxy for application date.
- **Stylised behaviours.** Distributions were designed to be plausible for
  West-African microfinance, not estimated from real portfolios.

## Intended use

Testing the pipeline end to end, demonstrating the methodology (temporal
validation, calibration, uncertainty-aware decisions, fairness checks).
**Not** for training a model used on real applicants.

## Regenerating a dataset without these files

`uv run avalix-bootstrap` produces a dataset with the simplified generator in
`avalix.data.ingest.generate_synthetic`. It is **different** from this
reference dataset and does not reproduce the audit figures.
